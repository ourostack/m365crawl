# Windows OWA acceptance process owner

This Windows-only supervisor runs the existing precompiled Go acceptance test, not another importer. The test refuses before discovery unless this supervisor's protected ownership, live process identities, native workspace identity, reviewed binary digest and exact test selection all match. An environment flag or a zero-exit executable cannot qualify. **Host execution still requires the parent's independent enabling review and explicit approval; the copied-synthetic proofs are not real-cache acceptance or release approval.**

Build with `GOWORK=off go build -o <owned-supervisor.exe> ./scripts/owaacceptance` and `GOWORK=off go test -c -tags acceptance -o <owned-acceptance.test.exe> ./acceptance`. Use absolute binary paths. Never build a real-data capture into Git or run the entire real acceptance suite when qualifying only OWA mail.

```powershell
& <owned-supervisor.exe> -test-binary <reviewed-owned-acceptance.test.exe> -test-sha256 <reviewed-lowercase-sha256> -outlook-root <explicit-source-EBWebView> -scratch-parent <existing-private-validation-parent> -receipt-dir <explicit-new-private-receipt-directory>
```

All paths are absolute, clean and non-reparse; scratch and receipts are outside Git. Argument parsing failures emit only a fixed refusal code, not the supplied argument or default flag diagnostics. The receipt directory is created/protected or verified already private, never broadened or scavenged. Every record is create-new, never an overwrite. The supervisor creates a uniquely owned workspace, locks its DACL to the current user and SYSTEM before any child payload write, then records its native volume/file identity. Child TEMP/TMP/TMPDIR and home/default application-data paths are redirected there. Inherited unrequested product/profile, OWA test, coverage and diagnostic variables are removed. The test receives only the recorded Outlook source and a nonexistent Teams root. The source is read-only; the ordinary archive and browser profile are not used.

Before the first mkdir, ACL change or record write, storage placement rejects a scratch parent or receipt directory equal to or beneath the source. The child repeats that boundary check for its actual TEMP and receipt roles before discovery. Comparisons walk directory components and compare complete native volume/file identities, not string prefixes: case variants, short names and volume-name aliases cannot hide source ancestry. Reparse aliases remain refused by the existing identity policy. A common ancestor alone is not overlap; a validation parent containing safe source/TEMP/receipt siblings is allowed, including receipt/scratch parent-child layouts whose generated TEMP is outside the source.

`ownership.json` is flushed and closed before launch: version, nonce, expected test, binary SHA256/native identity, exact workspace path/native identity, explicit source and supervisor PID/creation identity. `adopted.json` adds child PID/creation identity and adoption state while the job-owned leader is still suspended. Both remain immutable. A read-only-sharing handle pins executable bytes and identity throughout launch/run; the child independently hashes itself and checks both records, live supervisor/child creation identities, private workspace/native identity, redirected defaults and the exact two approved test arguments. This witnesses reviewed local bytes, not a security capability against a malicious same-user administrator or hostile arbitrary binary.

The child starts suspended and enters an unnamed kill-on-close Windows Job Object before its initial thread resumes. Standard output/error go to the null device, so even a crash cannot publish a raw payload. The test's existing two-minute cooperative work budget remains; the child test has a four-minute timeout and the supervisor terminates the owned job after five minutes. These are operational ceilings, not performance promises.

After a successful process start, qualified runs attempt a create-new protected `started.json` recovery record before job assignment: nonce, exact started PID and queried creation identity, with an explicit `identity_known` flag. This does not mark adoption or replace `adopted.json`. An identity-query failure records unknown identity and refuses; record-write failure refuses without claiming durable recovery. A process-start-to-record crash window remains unproved. The parent must match any recovered record to the protected initial ownership and actual native generation before taking action.

Startup failure cleanup has one shared deadline, no later than the existing run deadline and at most five seconds from the start attempt. Assignment/adoption/resume errors cannot call an unbounded Go process wait on a suspended leader. The supervisor first attempts the existing job release barrier when assigned; if that barrier refuses, it may terminate only the already-held exact leader handle, never a guessed PID. It reaps only after that handle signals within the remaining startup budget. Without a handle or signal proof, it releases the Go process wrapper without launching a wait goroutine, returns fixed failure codes and retains the protected workspace. A failed job barrier remains an unproved-consumer result even if the leader itself signals; kill-on-close is not substituted for verified release. The initial error and cleanup/closure failures are preserved together. Native/kernel call latency cannot be hard-preempted by this deadline.

On normal, nonzero or timed-out child exit, the supervisor first seals process birth with a verified active-process limit of one: any still-running job member already occupies the sole slot, so no new descendant can join after the inventory barrier. Existing members are not terminated by sealing. It then inventories job members, verifies each opened process handle belongs to this job (rather than trusting a recyclable PID), terminates the job, waits for those handles to signal and verifies zero active job processes. Member-handle waits and final zero-member observation share one five-second release deadline. No process-name killing occurs. The previously approved birth/membership and handle-disposal algorithms are unchanged.

Only the actual selected `TestRealOWAMailCountsAndRelationships` can emit `qualification.json`, after independent raw-source/archive/account/role/body/gzip/FTS and stability assertions succeed. Its witness cleanup is registered first and therefore runs last; `t.Failed()` prevents emission after an assertion or cleanup failure, and receipt write failure fails the test. The parent also requires overall child exit zero. Versioned strict JSON rejects missing/unknown/duplicate/null fields, duplicate counts, wrong native-array lengths, trailing/oversized input, malformed run identity and unsupported/negative/excess counts. Observed profiles must be positive and unstable profiles zero; the count-key set is exactly the existing raw census, not importer output.

Only after that release barrier does disposal pin the root and every ancestor against rename, validate the captured root identity, and enumerate non-reparse objects using native Windows handles that exclude delete sharing. All inventoried files and directories stay locked against replacement until bottom-up handle-bound deletion; no pathname delete or recursive wildcard deletion occurs. Native enumeration is required because ordinary Go directory opens do not share the pinned handles' DELETE access. Inventory is bounded to 131072 objects and depth 128; excess is an explicit refusal, not truncated cleanup. An uninventoried arrival makes deletion of its nonempty directory fail and retains it rather than erasing an unvalidated object.

Missing binaries, ownership changes, reparse paths, ACL changes, failed birth/membership barriers, unverified consumers or failed deletion return failure; an unverified-consumer failure leaves the protected workspace in place rather than deleting under a live reader.

The parent validates the witness after consumer release and before disposal. Durable `closeout.json` records pass/test failure/timeout/refusal/retention, exit, consumer and native-close proof, and actual absent/retained-owned/retained-unverified root identity. Only witness + exit zero + verified native release/disposal yields `status=qualified`, with the fixed census counts and binary/test witness, never raw JSON, paths, payloads or decoder errors. Protected ownership/closeout records contain private source/workspace paths for recovery and must not be pasted into public receipts.

The closeout decoder requires adopted ownership for every qualified/passed record; existing ownership validation then requires a nonzero child PID/creation identity distinct from the supervisor. Pre-adoption refusal and retained recovery records remain valid and unqualified. This resolves the standalone E2 consistency gap without changing wire version or replacing the parent's separate adopted-witness/run matching.

This protects against abnormal **test-process** exits while the supervisor is alive. Supervisor termination after adoption closes the job handle and kills its descendants, but does not execute file cleanup; host crash/reboot also does not prove cleanup. Death in the pre-adoption suspended window is not certified job-owned termination. Storage/flush/ACL/close failures can prevent a durable record or closeout; that is refusal, not a durability guarantee.

**The parent must own the outer tracked-process lifecycle.** Record the exact supervisor PID/creation identity and explicit protected receipt/scratch roots before invocation, wait for the tracked supervisor to exit even on timeout/failure, and reconcile its protected initial/adopted/closeout records against actual process creation/native root identities. If closeout is absent or consumers are unproved, establish release of every exact recorded consumer (including the pre-adoption window) before inspecting/removing payload. Revalidate the retained root's protected ACL/native identity, use the approved identity-bound owned disposal or retain it explicitly, and read back actual absence/retention. Environment reset in `finally`, elapsed time, a missing PID, or a filename prefix is not this proof. Never kill by process name, sweep a prefix, automatically overwrite receipts, or delete under an unverified reader.

Operational ceilings remain refusals, not mailbox/server completeness thresholds: JSON 32 KiB per record, reviewed executable 128 MiB, inventory 131072 objects/depth128, source observation 32768 files/512 MiB, individual raw/resolved/body payload 8 MiB, aggregate decoded payload/archive state/query projection each 512 MiB, primary raw records/object fields/array elements 16384, projected SQL rows 131072, HTML 262144 tokens and two-minute cooperative work. Witness aggregate values/profile count are bounded by `1<<30`. The independent oracle's conflict/malformed-detail, HTML encoding/rawtext/foreign/incomplete-token and unstable-source refusals are not waived by a valid guard.

The three aggregate ceilings allow measured cache volume rather than asserting mail correctness or completeness. Resolved payload size is checked before V8 deserialization/retention; query projected rows/bytes are counted before result materialization; archive-state tables consume a shared remaining byte budget through that same preflight. Exceeding any ceiling refuses without filtering, skipping or truncating observations. `aggregate_payload_budget` distinguishes decoded aggregate refusal from individual-record resource refusal; query/state helpers use fixed `query_projection_budget`/`archive_state_budget` errors and their already stage-bound diagnostics.

The separate `owaMaxProjectionRows` allowance applies only to SQL preflight/result materialization, including fixed archive-state queries. It does not expand `owaMaxQueryRows`, which retains the 16384 primary raw-record/object/array ceiling. A child relationship table may have many rows per primary message; private synthetic proof materializes 20000 actual recipient rows and retains all of them in archive state, while exact/excess tests enforce 131072 projected rows and unchanged byte limits. This is a finite operational allowance motivated by inherited collector counts, not an independent expected-source oracle, server/mailbox completeness claim, live performance proof or hard RSS guarantee.

Archive state charges each table's exact admitted SQL preflight byte count, including BLOB-cast numeric columns, against the cumulative allowance. The measured query helper returns that one count with its admitted result; the existing unmeasured query wrappers retain their interfaces. State does not reserialize values, rerun a separate count formula or ignore numeric overhead. A small actual archive test passes precisely the summed projection and refuses one byte less.

These are accounted-byte bounds, not hard RSS limits. The resolver may allocate a payload before its size check; V8 objects, strings/maps, copied source, gzip/text derivatives, SQLite projection work, result slices and simultaneous comparison/baseline state can duplicate bytes. The two-minute cooperative and outer native timeouts remain, without a host performance guarantee. Synthetic proofs exercise >64 MiB decoded/state data and >32 MiB projected results plus exact/excess budget checks; they are not a live copied-mailbox benchmark.

### Failed-test diagnostic witness

The independent raw census separately implements the product's narrow OWA metadata policy: zero-store matching name entries are excluded when a populated match exists; two populated matches, including partial layouts, still refuse. All-zero matches and missing/duplicate required stores remain layout refusals, not empty positive acceptance. A synthetic copied-source test inserts only an additional empty database-name metadata entry and proves ordinary Open/Collect/cold-repeat-forced Run and independent census/archive agreement without changing the committed fixture.

The raw folder oracle independently applies mapper-v3 root attribution: a unique case-normalized distinguished `msgfolderroot` anchors the mail tree only if all message ParentFolders and inbox/sent core folders descend through it and every observed component is acyclic/shape-valid. Its RootID remains the anchor tree's actual opaque external root. Unreferenced noncore components remain in the census/archive; no largest-component, display-name or ID-pattern heuristic is used. Multiple anchors, foreign relevant folders or cycles refuse clean acceptance. With no anchor, the legacy unique external-root rule remains. Copied-synthetic tests prove all rows retained, normal Open/Collect/Run agreement, persisted previous-root reread/unchanged skip and safe trusted-absence/reappearance; these are not host qualification or live stability claims.

Child stdout/stderr remain discarded. On failure only, the actual selected test's last-running cleanup attempts a create-new protected `diagnostic.json` instead of a pass witness. It first writes/syncs/closes `diagnostic-pending.json`, then publishes by a native same-directory move that does not overwrite an existing final record. An incomplete/refused pending write cannot expose a final diagnostic to the consumer. It records the same version/test/nonce/binary/native-root/adopted-process identity, outcome `failed`, one fixed stage and optional fixed field names; never test output, raw errors, paths or source values. Success still emits only the existing qualification witness and requires every cleanup plus overall child exit zero.

Stages are `guard`, `discovery`, `capture`, `independent_census`, `import_repeat_compare`, `global_accounts`, `source_stability` and `cleanup`. Capture owns source/resource checks, fingerprint/copy/shape and copied-payload integrity work; the independent census owns case-sensitive raw decoding/HTML/detail-conflict coverage; import owns the ordinary cold/repeat/forced `Run` and archive comparisons; global accounts owns the full observation-set comparison. The first responsible failed operation is retained even as later cleanups run. A new cleanup failure after successful work is `cleanup`, not the last successful import phase. This is a phase diagnostic, not a mailbox-parity verdict or raw exception classification.

Field names must belong to the literal allowlist in `protocol/diagnostic.go`: the existing message/comparator/aggregate fields and six raw detail fields (`ToRecipients`, `CcRecipients`, `BccRecipients`, `Attachments`, `UID`, `InternetMessageId`). Fields are required as an array, may be empty, and cannot contain unknown/duplicate/null entries. They are supplied only from the existing fixed comparator or typed coverage refusal, never arbitrary error strings. Strict diagnostic decoding rejects unknown/missing/trailing/oversized fields, unknown stages, wrong outcome and wrong adopted run/test/hash/native/process identity.

After the owned consumer release barrier, a nonzero child exit may contribute that validated private diagnostic to an **unqualified** public packet containing only fixed stage, reason, allowlisted field names and, for a source-omission refusal only, bounded fixed loss-code counts. It cannot replace a qualification witness or turn a test failure into success. Missing/invalid/foreign diagnostics, failed diagnostic writes, timeout, native cleanup/closeout failure or unproved lifecycle produce `status=unqualified stage=unproved reason=unproved fields=[]`. Private closeout facts and parent tracked-process recovery remain binding, including the separate qualified-closeout adoption requirement. No new host invocation is authorized by its presence.

The diagnostic requires `reason` and `omissions`. One central stage-to-literal reason table in `protocol/diagnostic.go` serves producer mapping and strict wire validation. The independently approved census/HTML set remains exactly 32 codes; census error mapping still compares the complete error text and returns only a matching table constant. Unknown/private/wrapped/suffixed/case-mismatched errors map to `unproved`. Other stages record only the literal responsible failpoint before the existing fatal/error assertion, never arbitrary error text, source report serialization, SQL/decoder values or guessed causes.

Import reasons are `sync_refused`, `sync_source_refused`, `sync_status_mismatch`, `sync_counts_mismatch`, `archive_open_failed`, `archive_state_refused`, `archive_state_budget`, `query_projection_budget`, `repeat_archive_unstable` and `archive_mismatch`. Global accounts allows `archive_open_failed`, `account_isolation_mismatch` and `query_projection_budget`; stability allows `unstable_source_observation`; cleanup allows `snapshot_cleanup_failed`, `archive_cleanup_failed` and `archive_close_failed`. Guard/discovery/capture use their existing literal permit/discovery/copy/resource/integrity failpoints. `unproved` remains allowed at every valid stage. Query/state budget attribution recognizes only their exact fixed helper refusal, retains the first responsible failure and does not change admission, cumulative accounting, oracle results or import checks.

`omissions` is a required object, normally `{}`. Nonempty counts are legal only with `import_repeat_compare/sync_source_refused`. The literal 19-code product OWA allowlist covers the three shared mail mapping losses, duplicate/detail/root/source-change losses, generic reader omission, truncated-log-tail and ten supported fixed IndexedDB reader losses. Each count is a positive integer and the sum is at most 1,073,741,824; unknown keys, zero/negative/fractional/overflow/null counts, duplicate keys, missing/null objects and stage/reason mismatches refuse. Producer unknown or invalid source omissions produce `reason=unproved` with an empty map, never partial filtering or arbitrary key output. No source name, profile, error message, status string or report object is retained in the diagnostic; repeat-step/status fields are unnecessary to distinguish these fixed checks and are not added.

Validated failure output remains `status=unqualified stage=<fixed-stage> reason=<stage-allowlisted-code-or-unproved> fields=<allowlisted-array>`, appending `omissions=<fixed-code-integer-object>` only when nonempty. Invalid/missing reason or omission shape, unknown/mis-staged codes or unproved lifecycle fall back to `stage=unproved reason=unproved fields=[]`. Older diagnostics missing either required field refuse rather than receiving a permissive default. Qualification/success counts, null child output, strict adopted identity, source/oracle semantics, E1 placement and native disposal remain unchanged. A reason is a fixed observation of the responsible failed check, not permission to bypass it or an inference about a host source. Synthetic subprocesses exercise every import check, actual product conflict reporting, actual small archive/projection budgets, repeat/archive/global mismatch, source stability and cleanup refusal, plus first-failure retention through later failed cleanup.

`GOWORK=off go test -count=1 ./scripts/owaacceptance/...` uses only synthetic payloads. Existing disposal/barrier tests retain their meaning. Protocol/native tests exercise strict wire validation, absent/forged/stale ownership, pinned executable write/replacement refusal, exact selection, zero-exit unmatched/wrong/early-exit binaries, malformed witnesses and protected retained-root recovery. Set `OWA_ACCEPTANCE_TEST_BINARY` only to a locally compiled reviewed acceptance artifact to include copied-committed-fixture end-to-end success/nonzero/timeout/record-mismatch tests. The top-level environment stays realcache0; only the job-owned child gets realcache1 with its explicit private copied synthetic source and the same real guard. Without that explicit artifact, these tests skip rather than claiming actual-test qualification. The full acceptance suite stays opted out, and non-Windows real selection remains unsupported/refused.
