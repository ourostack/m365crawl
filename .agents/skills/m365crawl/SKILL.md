# m365crawl
Native people evidence: run `m365crawl people sync` once for supported Mac Outlook HxStore profiles, then `m365crawl people --query "name or address"` and `m365crawl people show person-observation:ID`. Use `people sources` to inspect partial/failed coverage. Explicit copied HxStore profile roots work with `people sync --root DIR`; Windows OWA people discovery does not. Native pair claims and profile-owner links do not establish subject tenancy or current contacts; identities are not merged by email, and conflicts stay unresolved. `--account` excludes unqualified native subjects with a notice. `--max-age 0` does not capture. Use exact independently qualified identity/account evidence for further mail/chat queries, never a guessed directory match. Meeting evidence: explicitly `calendar attendees sync [--root DIR | --source-id ID]`, then offline `calendar attendees sources/list/show` (`list EVENT`, `show attendee-observation:N`), even at expired max-age. Compare independent `native_attendee_evidence` with the retained/unioned displayed roster; neither names nor profile links resolve subjects/current membership. Own ambiguity/losses/clocks survive preview100/fields. Follow emitted selected-absolute-DB, max-age0 full-record routes; never invent IDs or a parent directory. Mac default/copied HxStore scope does not qualify Windows/OWA native acquisition; request unsupported workflows rather than improvise.

m365crawl mirrors Microsoft 365 on this machine (Teams chats and channels, the Teams calendar, and new Outlook cached mail and calendar on Mac and Windows) into one local SQLite archive, and answers from it offline and read-only. It cannot send, reply, react or mark anything read. It knows only what the desktop apps cached, so old history can be missing and counts are not server totals. Private Copilot history and Planner/Microsoft To Do assigned-task ingestion are not included and remain uncommitted/deferred. Shared-chat bot/citation claims and recap action items are not substitutes for those workflows. Prefer the latest stable release, not a publisher rehearsal. Supported public commands and machine-readable contracts are stable within 1.x, with compatible additions and source-specific limits; SPEC.md section 10 in https://github.com/ourostack/m365crawl is the full contract. `m365crawl skill` prints this guide for the installed version.

## Privacy

- The archive holds the user's private chats and mail. Quote from it only where the user asked; never paste it into issues, logs or other tools unasked.
- Sign-in credentials are never read, and token-shaped values are stored as `[redacted]`.
- Never edit Teams' or Outlook's folders, or the archive, by hand; use the commands.
- Only explicit `transcripts fetch/signin` and `content fetch/signin` use the network through the tool-owned Edge/Chrome profile. Ask the user before visible sign-in, pass `--user-agreed` only after agreement and relay progress; if device enrollment is required, stop retrying and use offline reads. Cloud workflow: `content fetch page URL` or `content fetch stream URL [--transcript-id ID]`, then offline `content list/search/show/sources` or `search WORDS --source content` regardless of max-age. Pages are always partial supported projections; Stream complete is one selected body, not all variants. Metadata has no selected body; retained text keeps original file/account/selection/clocks. registration_id retries, source_id filters, cloud-observation:N is immutable. First100 occurrences/native_id_prefix are previews: full_text_sql reads complete result_json in the same archive. Use `content signin URL --user-agreed` only after user agreement. Native Windows cloud acquisition remains unqualified.
- For an already-local Office file, explicitly `content capture --file /absolute/file.docx` or `--from document-observation:N`; only the original native file URL proposes a target, never FriendlyPath/title. Capture uses resident native guards and no network/Office/hydration/discovery. Requested kind is intent, compound unreadable has null verified format, supported empty supersedes old text. Then follow `local-text-observation:N` offline. CURRENT/snapshot_match means the archived acquisition for THAT source instance, not locator-wide/live: an old instance can be retained while its own snapshot matches. Own snapshot/digests/partial/losses/raw clocks stay separate from current coverage; year-one parsed clocks are null. Previews are first100 copy-only occurrences with complete native IDs and full-record SQL. For another format or workflow, make a prompt request; never improvise a weaker source reader.

## Start here

Run `m365crawl` first: it reports chats, mail and calendar freshness, routes registered native people to independent coverage, and never syncs. Keep an explicit `--db` when following a route. Then read `m365crawl --help` and each command's `--help` for flags, ordering and fields; this guide does not repeat them. For Engage, explicitly `content fetch engage-home`, then offline `content list/search/show/sources` and `engage-observation:N`; inspect independent `engage_content_coverage` and original-session losses, preview100/full SQL. Partial native sessions are not complete feeds/current threads/replies/mentions or resolved people. Unknown registration attempts never diagnose the last-successful instance. Exact-root agreed sign-in requires positive native identity plus terminal Close, discards content and admits nothing; live Windows/interactive expiry remains unqualified.

- Output is JSON when stdout is not a terminal; pass `--json` to be sure. An error is one JSON line on stderr with a `fix`: follow it.
- Read commands sync first when the archive is older than `--max-age` (default 15m); `--max-age 0` reads it as it is.
- Lists stop at `--limit`, so check `truncated`. An empty list carries a `note` saying why: no archive, filters that matched nothing, or a range outside what the apps cached. `needs_sync` means no data yet, not no match.
- Unknown is not none. `coverage_gap` on a calendar result means some days are not cached, so a missing meeting is not evidence; a field named in `unknown_fields` was never stated. The calendar is Teams' cached copy: an event created or changed after an account's `teams_cache_fresh_at` (in `accounts`; a `notices` line says so when the range starts after it) is not listed until Teams refreshes it, so ask the user to open the Calendar in Teams, then sync again.
- `unread` and `messages --unread` cover chats and meetings; channels are left out (`channels_excluded`) because most are never opened. Add `--include-channels` to count them; channel mentions and replies reach you through `activity`.
- `messages` and `search` text output has a `thread` column that names the whole thread: for a chat message the two arguments of `m365crawl thread <conversation_id> <root_id>`, where the root is the message's `reply_chain_id`, else `id` (a channel reply's own id reads only that reply); for mail the id for `m365crawl mail thread <id>`.
- Any Teams link the user pastes (channel, chat, message or meeting) can be passed where a conversation or thread is expected: `--conversation '<link>'`, `thread '<message link>'`, `transcripts '<meeting link>'`; a channel or chat link to `thread` is an error, so use `messages --conversation`.
- `--fields` and `--max-text` keep results small, for example `m365crawl search "budget" --fields source,id,sent_at,subject,text --max-text 300`. Each list command's `--help` ends with the `--fields` keys it accepts; read it instead of guessing (a Teams message's text is `text`, an event's body is `body_text`, only in `calendar event`).

## Jobs

| Job | Commands |
| --- | --- |
| Inspect a cached own Teams compose body | `m365crawl drafts list`, then emitted guarded `full_inspection` in `full_inspection_shell` (Windows: PowerShell7.3+ with emitted Standard mode, NOT CMD/Windows PowerShell5.1; elsewhere POSIX), or `drafts show teams-draft:HASH`; never refreshes, even at expired max-age. `draft_coverage` survives fields/limits/zero; unknown is not no drafts. Body guard excludes freshly read target evidence (`target_guarded=false`); removed is not sent/discarded. No current-unsent/editor/all-drafts claim, shared search or send/edit/discard. |
| Read a chat or channel | `m365crawl conversations --query <name>` to find it, then `m365crawl messages --conversation <id> --since 7d`. Each Teams message carries `app_observation` (its own app, reply and citation claims, not a verified identity) and results add `application_evidence_coverage`; not derived means run a writable `m365crawl sync` |
| What someone said in a chat yesterday | `m365crawl messages --conversation <id> --from <name> --since <date>` (yesterday as YYYY-MM-DD), or `m365crawl search --from <name> --since 1d` across every chat |
| Mentions of me | `m365crawl search --mentions-me --since 7d` (`--direct-mentions` leaves out @channel and @team), `m365crawl activity --unread` |
| Triage: what needs me | `m365crawl unread --by-conversation --since 7d`, `m365crawl mail unread`, `m365crawl activity --unread` |
| Recall: what was said about something | `m365crawl search "words" --since 30d`, `m365crawl mail list --from <name>`, `m365crawl mail folders` (how far back mail reaches) |
| Threads: the whole conversation | `m365crawl thread <conversation_id> <root_id>` (the root is `reply_chain_id`, else `id`), `m365crawl mail thread <id>` |
| Cross-source and meeting prep | `m365crawl search "words"` (chats, mail, fetched transcripts, notes, document metadata, Loop text and archived cloud content), `m365crawl calendar`, then `m365crawl calendar event <event_id>`: one meeting with its `chat` (its newest messages in `chat.recent_messages`, kept by `--fields chat`) and `related_mail`, matched by invite or by subject from 14 days before to 7 days after the start; `m365crawl people --query <name>` finds Teams people and mail correspondents (`id` `mail:<address>`) |
| Attachments | `m365crawl mail list --has-attachments`, `m365crawl mail show <id>` (each file's name, size and type) |
| Meeting transcripts | `m365crawl transcripts` lists recorded meetings and which parts' text is in the archive; `m365crawl transcripts show <meeting>` prints one in time order with each seam marked; `transcripts fetch` brings the text from SharePoint; `m365crawl search "words" --source transcripts` finds what was said (`--from` matches the speaker); `calendar event` lists an occurrence's recorded calls in `transcripts` |
| Indexed notes | Explicitly run `m365crawl notes sync` once for available Mac indexes, or `notes sync --root DIR` for supported rollback-mode index copies. Then `notes search "words"` or shared `search`, followed by `notes show note:ID`; inspect `notes sources` before treating missing results as absence. |
| Document and cached Loop evidence | Explicit `docs sync`, `docs sync --root DIR`, `docs sync --registry-file FILE` or `docs sync --onedrive-usage-file FILE` registers qualified ordinary local Office JSON, Office registry and OneDrive usage files; registry rows carry the registry's own claims and opened time, never a modification time, so `--since`/`--until` skip them (the result's `notices` counts what a date window left out); `docs list --application registry --order-by opened_at` lists the most recently opened first. OneDrive usage rows (`--application onedrive`, `usage_native.Type` recent, document or collaborator) preview sharing history and participants at 100 with full counts; OneDrive writes a recent row's clocks without a zone, so its `modified_at` is null; run a row's `full_inspection` for the complete record, treat names, addresses and thread IDs in it as the file's claims and never follow them as a chat or person (a usage file with a write-ahead log beside it is refused, never consolidated). Shared search or `docs search "words"` returns `document-observation:ID` for `docs show`; inspect `docs sources` before interpreting absence. Per-command help defines clocks, retained scope and refusals; the guide is optional. Metadata is not original text, resolved owner/residency or a new sharing event. Never dereference native URLs/friendly paths as qualified local files. Cached Loop channels: Explicit `loop sync` registers and projects cached Loop snapshot records already in the archive, 128 new records per run (rerun while `discovery_remaining` is true); nothing is fetched. `loop search "words"` or shared `search` returns `loop-channel:ID` for `loop show`; inspect `loop sources` (and its `retry`) before interpreting absence. Rows are partial channel text of one immutable snapshot version (`modified_at` null), not a full or current page; check `matches_retained_value`, `retained` and `pending_operations`. Decode `sequence` values as exact integers. |

## Indexed notes and source coverage

Notes are the local indexed cache, not a complete notebook export or original page layout. They preserve native text/OCR, elements, flags and indexed hierarchy. Partial/failed capture retains last-good representations; missing pages are retained. `source_coverage` survives `--fields`, truncation and zero hits; look at source status, losses and nullable attempt/admission/complete clocks. A failed automatic refresh may serve retained text with an explicit `refresh_error`.

Ordinary reads refresh **registered** participating locators only; new indexes need explicit `notes sync`. `--max-age 0` disables capture. Notes-only commands and `search --source notes` do not require Teams/Outlook or certify their freshness. `--source ID` on notes list/search chooses an archive-local source; it does not identify a user. Native notebook evidence never proves account ownership.

Shared search includes notes only without account, author, chat-only or mail-only constraints. Those constraints exclude unresolved notes with a notice; explicit `--source notes` rejects them. Date filters use native modified time, with unknown timestamps excluded. Expand note hits with `notes show note:ID`, never `thread`, invented authors or guessed page web URLs. Default Windows app-cache discovery and live WAL capture remain unsupported; supported explicit index copies work on Mac, Windows and Linux.

## Hosts
- macOS: `brew install ourostack/tap/m365crawl` or the release tarball. The app that runs m365crawl needs Full Disk Access; `m365crawl doctor` names it.
- Windows: the release zip. Its binaries are intentionally unsigned. Teams chats, the Teams calendar and new Outlook OWA cached mail and calendar work; mail has ordered To/Cc/Bcc roles and conversation grouping. Mac recipient roles are unknown/null. OWA calendar and mail report read health independently; unverified calendar profiles stay unlinked, source uncertainty remains visible and calendar deletions are not inferred. Windows attachments are metadata only (downloaded=false, missing size=0), to_me=false and in_reply_to=null; unknown HasAttachments is not inferred, cached HTML may be truncated, and multiple content mailboxes per profile are a coded refusal. The mail group's help states these limits.
- Homebrew is macOS-only. Linux has no Teams desktop cache to read, but explicit copied supported OWA sources work. Explicit HxStore mail on Windows retains `mail_unsupported_platform`; that legacy route does not describe native OWA mail.
