# m365crawl v0.9.12

**Fetch meeting transcripts from Microsoft dogfood SharePoint hosts instead of rejecting valid cached references before retrieval.**

## SharePoint dogfood transcript recovery

Transcript retrieval now recognizes tenant hosts under `.sharepoint-df.com`,
including personal sites, alongside the existing SharePoint domains.
Existing cached drive-item references become eligible immediately: no source-row
repair, mapper rebuild or new sync is needed.

```sh
m365crawl transcripts list CALL_ID
m365crawl transcripts fetch CALL_ID --timeout 2m
m365crawl transcripts show CALL_ID
```

The existing tool-owned, headless browser performs retrieval with its existing
session. Host recognition does not grant access, establish sign-in or prove that
a file has a transcript. Genuine sign-in, access, availability and per-part
failures remain distinct.

Every discovered part keeps its own outcome and place in the transcript.
Check all parts and `complete` before relying on the result: a short
transcribe-only preamble is not a substitute for the recorded discussion.
Successfully archived text remains available offline.

## Narrow admission and clearer diagnostics

Only the exact `.sharepoint-df.com` suffix is added. Plain-host, nonempty tenant
and label, site-root, drive/item/transcript identifier and drive-item-quality
checks are unchanged. Suffix lookalikes, URL-like hosts and malformed references
remain unfetchable; no arbitrary-host override is introduced.

An unsupported host now has its own fixed explanation instead of being
indistinguishable from a malformed site root or identifier. The explanation does
not echo the cached host.

## Upgrade and platform scope

Upgrading from 0.9.11 does not change schema 18, native part identities, stored
references or existing transcript text. Back up an older archive before a
writable upgrade, as with earlier releases.

On macOS, use `brew install ourostack/tap/m365crawl` or
`brew upgrade m365crawl`, or verify the matching Darwin tarball against
`checksums.txt`. Darwin binaries are Developer ID signed and notarized.

On Windows, download the matching amd64 or arm64 ZIP, verify its checksum, unzip
it and run `m365crawl.exe` from your user-owned installation. **Windows binaries
are intentionally unsigned.**

The portable admission and retrieval-planning correction does not establish a
new live Windows service/authentication qualification. Browser ownership,
explicit sign-in agreement, timeout, cancellation and per-part save behavior
are unchanged.

The separate Engage text-bound correction is not included in this hotfix.
