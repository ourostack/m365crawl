# m365crawl v0.9.11

**Capture a bounded Engage Home session explicitly, then inspect and search its thread starters offline.**

## Explicit capture, offline follow-ups

```sh
m365crawl content fetch engage-home
m365crawl content list
m365crawl search "words" --source content
```

The fetch uses the tool-owned browser profile and the fixed Engage service root. It observes native session evidence, closes the browser, and only then publishes a successful capture to the selected archive. No arbitrary URL, thread, account or pagination selector is accepted.

Use the stable `engage-observation:ID` returned by list/search with `content show`. Ordered duplicate occurrences and empty blocks remain distinct. Previews show the first 100 blocks; complete native fields and the original session are available through the printed same-archive full-record command and SQL.

Ordinary content reads remain archive-only, even when `--max-age` has expired. They do not fetch, start a browser, migrate or repair the archive.

## Evidence, not a complete feed

These are partial native access-session thread-starter observations—not a complete/current feed, replies, mentions, requested-thread retrieval, assigned tasks or a directory/person join. Metadata-only is neither a no-access result nor a healthy empty-feed claim.

Immutable sessions preserve original native fields, raw and nullable parsed clocks, losses and first-capture identity. An exact return to an earlier representation reuses its original occurrence IDs and clocks. Missing content or later failures do not erase useful retained evidence.

`content sources` distinguishes registration diagnostics from native account instances. A failed or unavailable attempt has unknown account attribution; it does not mark a previous successful account active or move that instance's original session clocks.

Engage sign-in is separate and requires explicit user agreement. Native service evidence and terminal browser closure are required for verification; a visible Home shell alone is not enough. Sign-in discards observed content and does not admit it to the archive.

## Mixed content output stays truthful

Text output separates incompatible content/source schemas into correctly labeled consecutive tables, preserving selected order. Registration outcome/account-state/reason/retry labels no longer appear under instance/session headers.

Mixed search now consistently puts known clocks before unknown clocks and preserves established family precedence at equal clocks. This deliberately changes the exceptional legacy ordering that put an unknown year-one sentinel before a known pre-year-one instant; native bytes, IDs and clocks are not rewritten.

## Upgrade and platform scope

This release adds schema 18 without changing existing public IDs or deleting retained archive content. Back up an older archive before the first writable upgraded command.

On macOS, use `brew install ourostack/tap/m365crawl` or `brew upgrade m365crawl`, or verify the matching Darwin tarball against `checksums.txt`. Darwin binaries are Developer ID signed and notarized.

On Windows, download the matching amd64 or arm64 ZIP, verify its checksum, unzip it and replace `m365crawl.exe` in your user-owned installation. **Windows binaries are intentionally unsigned.**

Actual Mac native capture and offline consumers qualify this acquisition path. Native platform fixtures and portable archive reads do not establish live Windows/Linux Engage acquisition or interactive sign-in challenge/expiry behavior.

Existing SharePoint/Stream explicit-selection recovery and resident-text archive/request scope remain unchanged. Planner/To Do assignments, private Copilot history and fuller Outlook attendee integration are not added by this release.
