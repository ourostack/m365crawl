# m365crawl v1.7.1

**Meetings with a recording still processing no longer read complete.**

A compatible patch release on the stable 1.x line.

## Fixed

- Transcript listings now include recordings that Teams is still processing, with a reason telling you to sync again in a few minutes. Teams says a recording is processing before it publishes the file, and until now such a recording was missing from the list, so a meeting with a second recording still on its way looked complete. A processing recording, or one Teams reports as failed, now keeps the meeting `partial` and `transcripts show` at `complete: false` until the ready notice arrives. Parts already fetched keep their text.

## Coverage and upgrade

No archive schema change. The transcript parts mapper rises to version 2, so the next sync rebuilds transcript parts from messages already in the archive, with no new network reads.

Real-cache acceptance and native Windows checks were not part of this release's qualification. The fix was tested with synthetic recording notices only.

## Install

On macOS, use `brew install --cask ourostack/tap/m365crawl` or `brew upgrade --cask m365crawl`, or verify the matching Darwin tarball against `checksums.txt`. Darwin binaries are Developer ID signed and notarized by the normal release pipeline.

On Windows, download `m365crawl_1.7.1_windows_amd64.zip` or `m365crawl_1.7.1_windows_arm64.zip`, verify it against `checksums.txt`, unzip into a user-owned directory and run `m365crawl.exe`.
**Windows binaries are intentionally unsigned.**
