# m365crawl v0.9.2

**Find the document trail, not a guessed document.** Your agent can now search
supported Office recent, shared, recommended and Open-dialog metadata in the
same local archive as Teams, Outlook and OneNote. Inspect the original source
claims, follow a stable observation ID and keep independent coverage visible.
No referenced document is opened or downloaded by this workflow.
The [document contract](https://github.com/ourostack/m365crawl/blob/v0.9.2/SPEC.md)
defines the supported metadata scope.

## Start from help

```sh
m365crawl docs --help
m365crawl docs sync
m365crawl --max-age 0 docs list --limit 5
m365crawl --max-age 0 search "project" --source documents
m365crawl --max-age 0 docs show document-observation:ID
m365crawl --max-age 0 docs sources
```

Use an observation ID returned by list or search, and preserve an explicit
`--db` when following a command. `docs sync` discovers the supported finite
Mac Office cache layout. `docs sync --root DIR` selects supported ordinary
caller-supplied surface JSON files; Windows does not gain default Office app
discovery. Ordinary reads refresh registered participating sources only.
`--max-age 0` is archive-only: no capture or schema migration.
See the [command reference](https://github.com/ourostack/m365crawl/blob/v0.9.2/docs/commands.md)
for accepted options and fields.

## Metadata with receipts

Document observations keep immutable native representations, original
acquisition and source-file clocks, retained rolling-list history and exact
URL-reference occurrences. Document rows and their independent coverage
share coherent read snapshots in list, detail and participating search.
Source failures remain separate from healthy results;
coverage survives projections, truncation and zero hits.

A title, native identifier, URL or matching reference is a source claim, not
resolved document identity, subject tenancy, current sharing authority or
proof that a local file is resident. Captured metadata is not original
document text. Native modification clocks, acquisition time, source-file
observation and archive admission have different meanings; unknown times
stay unknown. Detail explains these boundaries and previews at most 100
reference occurrences, with the full reference count and truncation state.

## Scope notices belong in text too

Source-only text results now preserve their existing notices. In particular,
an account-filtered people result explains when unresolved native subjects
were excluded, rather than presenting that exclusion as an ordinary
no-match. JSON meanings, identity boundaries and independent source
freshness are unchanged.
The [scope-notice correction](https://github.com/ourostack/m365crawl/pull/184)
preserves those existing result meanings.

## Install and upgrade

On macOS, use `brew install ourostack/tap/m365crawl` or
`brew upgrade m365crawl` for an existing cask installation. Alternatively,
download the matching Darwin tarball and verify it against `checksums.txt`.
Darwin binaries are Developer ID signed and notarized.

On Windows, download the matching amd64 or arm64 zip, verify its checksum,
unzip it and replace the executable in your user-owned installation.
**Windows binaries are intentionally unsigned.** Supported supplied local
JSON inputs remain subject to the same positive native admission and cleanup
guards; a supplied input is not default app discovery.

For example, from the directory containing the Windows executable:

```powershell
.\m365crawl.exe docs sync --root "C:\path\to\office-json"
```

Use supported ordinary `recent.json`, `shared.json`, `recommended.json` or
`dialog.json` inputs, not arbitrary original documents.

This release uses archive schema 11. Normal acquisition commands perform
the supported migration; do not edit the archive manually. Run
`m365crawl doctor` after upgrading. Start ordinary workflows from CLI help;
`m365crawl skill` is an optional version-matched strategy guide, not a
prerequisite for understanding flags, scope or follow-ups.

## Usage-led, not exhaustive

Registry and OneDrive consumers, original local document text, cached Loop,
additional cloud consumers and current full-attendee joins remain separate
work. This release does not promise complete Microsoft 365 export.

For another app or workflow, work with your agent to open a
[prompt request](https://github.com/ourostack/m365crawl/issues/new?template=prompt-request.yml).
Describe the job and use synthetic examples; never attach private caches,
archives, document content or credentials.
