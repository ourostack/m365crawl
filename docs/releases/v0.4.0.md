# teamscrawl v0.4.0

`v0.4.0` reads the new Outlook for Mac calendar by default, links it to your Teams account on its own when they are the same person, notices events you delete in Outlook, and fixes Outlook locations and previews. The archive upgrades in place on the first sync.

## Changed

- **Outlook is on by default.** When the new Outlook for Mac has a profile on this Mac, `sync` and the read commands read its calendar with no flag. `--outlook-root none` (or `TEAMSCRAWL_OUTLOOK_ROOT=none`) turns it off. `--teams-root` without `--outlook-root` still keeps it off, so tests and fixtures never read a real profile. `TEAMSCRAWL_OUTLOOK=1` is still accepted and does nothing now.
- **Outlook never gets in the way of Teams.** No Outlook, or no profile, is not an error. A profile that cannot be read (no Full Disk Access, a store this build does not read) shows as a source with status `unavailable` and a fix, and the run's status and exit code do not change. `doctor` passes in all of those cases and warns only when something is wrong with a root you named or a profile it should read.

## Added

- **Automatic link by proven identity.** A sync links an Outlook profile to a Teams account (`link: address` in `calendar sources`) when an account signed in to the profile has the same address as that Teams account, ignoring case. It links only when exactly one Teams account matches. A link you set with `--outlook-account`, or ended with `--outlook-account none`, always wins. With the link, a meeting both apps hold is one item with `sources: ["teams","outlook"]`, not two. On a real copy: 107 items over 14 days, 89 from both sources, 0 listed twice.
- **Deleted Outlook events are marked gone.** Outlook writes no deletion marker: a deleted event stays in its store until Outlook compacts the file, which took 4 to 16 minutes in our test. teamscrawl marks an event gone (`removed_at`, its data kept) when two syncs in a row, reading different copies of the store, both miss it, so one damaged copy cannot hide a live meeting. It never judges series masters, events that start more than 60 days back (Outlook drops those on its own), or a read that lost data. `calendar sources` reports `deletions: "inferred"`.

## Fixed

- **Outlook location and body preview.** An Outlook event with no location or no body showed its subject in those fields, and after a rename, its old subject. On a real copy, every one of 3,374 events had a location and a preview, and 318 locations were the subject. Now 3,027 have a location, 3,272 have a preview, and none equals the subject. The archive re-reads its Outlook events on the next sync.
- **All-day Outlook events:** the docs and the skill now say to read the day from `start_date` and `end_date`, because the store labels the time `UTC`.

## Install

### macOS

```sh
brew upgrade ourostack/tap/teamscrawl
```

Or download `teamscrawl_<version>_darwin_arm64.tar.gz` or `teamscrawl_<version>_darwin_amd64.tar.gz` from the release assets.

Reading Outlook needs the same Full Disk Access grant as Teams (see docs/full-disk-access.md).

### Windows

Download `teamscrawl_<version>_windows_amd64.zip` or `teamscrawl_<version>_windows_arm64.zip`, unzip it, and run `teamscrawl.exe`. The Outlook source reads the new Outlook for Mac only, so on Windows it stays off and the Teams sync is unchanged.
