# m365crawl v0.9.1

**Start from help, not guesswork.** People workflows now explain their options, empty results and independent coverage directly in the CLI. This patch fixes discoverability in the native people workflow without adding identity resolution, acquisition sources or a new archive schema.

## Find the right workflow from the CLI

```sh
m365crawl people --help
m365crawl --max-age 0
m365crawl --max-age 0 people --query "name or address" --limit 5
m365crawl --max-age 0 people sources
```

`people --help` now exposes the actual default list's query and limit definitions, accepted field keys and ordering. Existing `people show person-observation:ID` follow-ups and Teams/mail identifiers keep their meanings.

The read-only overview still reports chats, mail and calendar independently. When native people sources are registered, it also gives an archive-only people coverage route. Keep an explicit `--db` when following that route and omit unsupported subject `--account` filtering. The legacy source table is not a contact-completeness assessment.

An empty native or combined people list now explains that no archived person matched and points to source coverage. Partial, failed and retained source state remains visible outside `--fields`; a zero-hit result is not proof that a person does not exist.

## Keep the evidence boundaries

Native people remain unresolved source observations. Matching names or email addresses do not merge identities; a profile-owner link does not establish the subject's tenant. Original capture/source clocks and legacy `last_seen_at` are not current-contact authority.

This patch keeps archive schema 10 and the existing acquisition contract. Default native people discovery remains Mac Outlook HxStore only; supported copied HxStore roots are portable. Windows OWA people discovery, current full-attendee joins, documents, cached Loop and additional cloud consumers are not added here. See the [people release](https://github.com/ourostack/m365crawl/releases/tag/v0.9.0), [changelog](https://github.com/ourostack/m365crawl/blob/v0.9.1/CHANGELOG.md) and [command reference](https://github.com/ourostack/m365crawl/blob/v0.9.1/docs/commands.md).

## Install or upgrade

On macOS, run `brew install ourostack/tap/m365crawl`, or `brew upgrade m365crawl` for an existing cask installation. Alternatively, download the matching `m365crawl_0.9.1_darwin_arm64.tar.gz` or `m365crawl_0.9.1_darwin_amd64.tar.gz` and verify it against `checksums.txt`. Darwin binaries are Developer ID signed and notarized.

On Windows, verify the matching `m365crawl_0.9.1_windows_amd64.zip` or `m365crawl_0.9.1_windows_arm64.zip` against `checksums.txt`, then replace the existing executable under your user profile. **Windows binaries are intentionally unsigned.** The existing archive/privacy rules still apply. Upgrades from older schema versions use normal product commands; do not alter the archive manually.

After installing, run `m365crawl doctor`. `m365crawl skill` supplies a version-matched workflow guide, but basic options, scope and follow-ups belong in command help and ordinary output. For another app or missing workflow, work with your agent to [open a prompt request](https://github.com/ourostack/m365crawl/issues/new?template=prompt-request.yml) without attaching private content, caches, archives or credentials.
