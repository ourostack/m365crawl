# m365crawl v1.5.0

**Say which days the archive covers, fetch only the missing mail range through WorkIQ, and let a person turn on directed writes.**

A compatible addition on the stable 1.x line. Existing commands, flags and field meanings are preserved. One default narrows on purpose: a read no longer syncs this machine's data into an archive this machine does not feed (see upgrade notes).

## New

- `m365crawl coverage` says, per day and source (Sent Items, Inbox, chats, meeting chats, channels, calendar), whether the archive holds everything the app cached: `covered`, `partial` or `not_covered`, with an exact item count, reasons and a fix. Use `--day`, or `--since`/`--until` for up to 31 days. `mail list`, `messages`, bounded `search` and the `calendar` agenda add the same verdict as `range_coverage`, so a real zero can be told from a day the archive does not cover.
- `workiq sync --source mail --since T [--until U]` fetches only the server mail in that range, and can prove the range complete (`--coverage proof`). A mail read whose range the archive does not cover now routes to a window of exactly the missing range instead of a whole-account sync.
- Directed writes through WorkIQ, off by default: send a Teams chat message, send new mail, reply, reply all, save, update or discard a mail draft, and add or remove a chat reaction (`m365crawl writes ...`). Every write names the agent and a reason; a message counts as sent only once it is read back from the server, and an outcome m365crawl cannot establish is `unknown` (exit 5) and never resent.
- `content fetch doc LINK` reads one OneDrive or SharePoint Office file through WorkIQ, keeping text only when WorkIQ reports that the file's rights allow extraction. Shared `search` includes those documents.
- Mail outputs add `folders`, every folder a Mac mail message is in with its read state.

## Fixed

- Mail on Mac no longer drops a message from `--folder sent` (or any folder) because another copy of it changed more recently; `mail folders` and `mail unread` count each copy where it is.
- A message with a copy in Sent Items is dated by its send time in every list.
- Opening the archive for a sync, including each `watch` tick, waits up to five seconds for another writer instead of failing with "database is locked".
- An archive whose schema number reached a feature without that feature's tables reads as not having the feature instead of failing.

## Upgrade notes

- **Schema 30.** The first writable open (a `sync`, or a read that syncs first) migrates the archive to schema 30: a 1.4.0 archive from 22, a 1.3.0 archive from 20. The new tables hold WorkIQ documents, mail folder membership, the directed write log and WorkIQ mail windows. Read-only opens of older archives do not migrate. Older binaries refuse the newer archive (`archive_newer`).
- **Writes are off.** Directed writes stay off until the person turns them on by typing `m365crawl writes on` on the controlling terminal; agents never run it. `m365crawl writes status` shows the switch, which is a file beside the archive, not part of the schema. The gates stop accidental writes; they are not a security boundary against an agent with shell access.
- **WorkIQ is still opt-in.** It needs the separately installed, signed-in WorkIQ CLI; installing it, signing in and accepting its EULA are one-time human steps that m365crawl never performs. Ordinary reads, plain `sync` and `watch` never launch it.
- **Reads on another archive no longer sync into it.** A read syncs first only into the default archive or an archive this machine's sources feed. A read with `--db` on a scratch file, a copy, another machine's archive or a test archive answers from the archive as it is, with `implicit_sync: "foreign_archive"` and a notice naming the explicit `m365crawl --db PATH sync` to run if you want this machine's data in it. A `--db` path with no archive is no longer created (`implicit_sync: "no_archive"`). An archive you already sync into keeps syncing; after moving one, run `sync` on it once.
- **Fill a missing mail range with a window.** When `range_coverage` or `coverage` reports mail `not_covered`, its route gives the exact `workiq sync --source mail --since ... --until ...` for that range, which fits on disk where a whole-account sync of a large mailbox does not.

## Not claimed

A live view-only refusal for protected documents has not been observed yet. Native WorkIQ service qualification, WorkIQ on Windows, several Windows Outlook content mailboxes on real data and complete server history are not claimed.

## Install

On macOS, use `brew install --cask ourostack/tap/m365crawl` or `brew upgrade --cask m365crawl`, or verify the matching Darwin tarball against `checksums.txt`. Darwin binaries are Developer ID signed and notarized by the normal release pipeline.

On Windows, download `m365crawl_1.5.0_windows_amd64.zip` or `m365crawl_1.5.0_windows_arm64.zip`, verify it against `checksums.txt`, unzip into a user-owned directory and run `m365crawl.exe`.
**Windows binaries are intentionally unsigned.**
