# m365crawl v0.9.8

**Fetch a SharePoint page or a Stream transcript explicitly, then read and search its captured content offline.**

## From a link to archived content

```sh
m365crawl content fetch page "https://example.sharepoint.com/sites/project/SitePages/Updates.aspx"
m365crawl content fetch stream "https://example.sharepoint.com/sites/project/_layouts/15/stream.aspx?id=%2Fsites%2Fproject%2FShared%20Documents%2Fvideo.mp4"
m365crawl content list
m365crawl content show cloud-observation:123
m365crawl search "launch plan" --source content
```

These are one-target captures, not a site crawler or automatic download. Ordinary `content list/search/show/sources` commands read only the archive, regardless of `--max-age`. They do not start a browser, sign in or refetch old content.

Fetches use m365crawl's own browser profile. If the service needs sign-in, the CLI points to the explicit `content signin URL` workflow. It never borrows your normal browser's authentication. A failed browser close cannot publish staged content.

## Know what was captured

SharePoint pages contain a bounded supported rich-text projection, not the complete rendered page. Controls the reader cannot interpret remain counted losses; page coverage stays partial even when the supported text is empty.

Stream captures the selected native transcript of one video, with ordered entries, stated speakers and raw/parsed offsets. An empty collection means `no_transcript`, not a successfully captured empty body. When several transcripts need a choice, supply the exact `--transcript-id` rather than guessing a language or selecting the first one.

Native file/account metadata, requested transcript selection and captured transcript selection remain separate evidence. The service account is not resolved to a Teams person or the document's author.

## Retained text keeps its own evidence

A later denied, unavailable or metadata-only result does not erase previously captured text or label it current. Read results distinguish retained observations, current source state and whether the transcript selection matches, differs or is unavailable. Repeated identical representations keep their original observation IDs and clocks.

Previews expose totals and clipping. `full_text_sql` supplies an archive-only query for the complete retained native result. Source coverage remains visible even when a search returns no rows or the global limit hides every content hit.

## Upgrade

The archive moves to schema 16. Back it up before a writable command. Older archive-only content reads report that this source is not yet captured rather than migrating the archive. An older binary refuses an archive after it has been upgraded.

The existing document, note, people, Loop and meeting-transcript commands keep their IDs and behavior. Shared search preserves the relative order of existing equal-time hits.

## Install and qualification

On macOS, use `brew install ourostack/tap/m365crawl` or `brew upgrade m365crawl`, or verify the matching Darwin tarball against `checksums.txt`. Darwin binaries are Developer ID signed and notarized.

On Windows, download the matching amd64 or arm64 zip, verify its checksum, unzip it and replace `m365crawl.exe` in your user-owned installation. **Windows binaries are intentionally unsigned.**

Representative live page and video capture, repeated immutable capture and offline full-record reads were verified on Mac through the normal tool-owned profile. Native Windows tests and portable archive contracts passed in CI; live Windows service acquisition is not yet qualified. Other tenants, denied/expired sessions and unsupported page controls are not implied by those checks.

## Scope

This release does not download original Office documents, traverse sites or libraries, reconstruct web parts, replay sharing tickets or infer a meeting from a video. Resident Office text is a separate upcoming unit. For another workflow, submit a [prompt request](https://github.com/ourostack/m365crawl/issues/new?template=prompt-request.yml) with synthetic examples, never private archives, content or credentials.
