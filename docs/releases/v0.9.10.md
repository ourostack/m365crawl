# m365crawl v0.9.10

**Follow the printed recovery command without losing your archive or your explicit content selection.**

## Recovery stays in the same archive

Generated content retries, error fixes and post-sign-in follow-ups now name the selected absolute `--db` archive and preserve safely quoted arguments. A local retry keeps the registered file and requested kind. A cloud retry keeps its archive-local registration, including an explicitly selected Stream transcript.

```sh
m365crawl --db "/absolute/path/archive.db" --max-age 0 content sources
```

Run the returned retry as printed after remedying the refusal. It repeats that stored request; it is not an automatic format correction or a new guess at the current transcript.

## Unsupported format is not a retry loop

A resident file rejected under the requested kind now gets actual-format inspection guidance instead of an unchanged failing command presented as its fix. If a different recognized filename extension can suggest an alternative request, the command labels it as extension intent, never a verified package format or guaranteed repair.

The original failed requested kind and selected document reference remain archived. Package verification, native residency guards and finite parser limits are unchanged. Compound unreadable, readable empty, unsupported and oversized outcomes remain distinct.

## Stream sign-in does not choose a different transcript

Generic Stream sign-in knows the target URL, not which stored transcript request the caller intends. Its Next command now lists same-archive source choices instead of advertising a default transcript fetch. Choose the exact stored registration retry explicitly. A page sign-in still offers its exact page continuation; sign-in agreement and the tool-owned profile boundary are unchanged.

Ordinary content reads and source inspection stay archive-only, regardless of `--max-age`; the recovery command is an explicit acquisition only when you choose to run it.

## Upgrade and install

This patch adds no schema migration beyond schema 17, no dependency and no browser-policy or native acquisition change. Back up the archive before upgrading an older schema through a writable command. Existing observation IDs, requested intent and native evidence remain intact.

On macOS, use `brew install ourostack/tap/m365crawl` or `brew upgrade m365crawl`, or verify the matching Darwin tarball against `checksums.txt`. Darwin binaries are Developer ID signed and notarized.

On Windows, download the matching amd64 or arm64 zip, verify its checksum, unzip it and replace `m365crawl.exe` in your user-owned installation. **Windows binaries are intentionally unsigned.**

The regression tests exercise standalone printed-command replay, shell-special archive and file names, original requested-kind evidence and a selected-transcript sign-in chain where another transcript is offered. Synthetic/native CI is not a claim of live Windows service acquisition, interactive sign-in challenge or expiry qualification.

See the [changelog](https://github.com/ourostack/m365crawl/blob/v0.9.10/CHANGELOG.md) and [SPEC](https://github.com/ourostack/m365crawl/blob/v0.9.10/SPEC.md) for the exact contract. This patch does not add Engage archive capture, Planner/To Do assignments, private Copilot history or broader document formats. For another workflow, submit a [prompt request](https://github.com/ourostack/m365crawl/issues/new?template=prompt-request.yml) with synthetic examples, never private archives, content or credentials.
