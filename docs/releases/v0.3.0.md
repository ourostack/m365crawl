# teamscrawl v0.3.0

`v0.3.0` adds a calendar. teamscrawl now mirrors the Teams calendar with its meeting recaps, and can read the new Outlook for Mac's calendar as a second source. teamscrawl stays read-only toward both apps, and the archive keeps what it has seen after the apps drop it.

## Highlights

- `calendar` prints the agenda for a range, merged across sources by person, with per-day coverage that tells an empty day from an unknown one.
- `calendar event <event>` shows one event in full: the Teams join link and dial-in, the meeting chat, rooms (text, structured locations and room-mailbox attendees), every attendee with their response, the body, attachment metadata, and the meeting recap with its summary, outline, action items with owners, mentions, speakers, and the recording and transcript links of each occurrence.
- `calendar actions` lists the action items of a range's recaps with their owners; `--mine` keeps yours.
- `calendar sources` reports, per account and source, what is linked, which days are covered, when each was last read and how much detail it holds.
- Outlook for Mac is an opt-in second source: pass `--outlook-root DIR`, set `TEAMSCRAWL_OUTLOOK_ROOT`, or set `TEAMSCRAWL_OUTLOOK=1` for the default directory. Link an Outlook profile to a Teams account with `--outlook-account <tenantId>/<userId>`, and the same meeting from both sources merges into one event: Teams keeps the Teams meeting (join link, dial-in, meeting chat, recaps and recordings), attendee and room lists are the union of both copies, and `filled_fields` and `overridden_fields` say what came from where. Outlook stays off by default until its deletion handling is verified.
- `doctor` warns when an account has no Teams calendar cache or it is more than 7 days old.
- `sync --full-read` re-reads every record, and a sync of a changed cache does work in proportion to what changed.
- The archive schema is version 5. A v0.2.0 archive is upgraded in place when it is next opened for writing and fills its calendar on the first sync from the records it already holds. Older builds refuse a version 5 archive with `archive_newer`.

## Install

### macOS

Install with Homebrew:

```sh
brew install ourostack/tap/teamscrawl
```

Or download `teamscrawl_<version>_darwin_arm64.tar.gz` or `teamscrawl_<version>_darwin_amd64.tar.gz` from the release assets.

### Windows

Download `teamscrawl_<version>_windows_amd64.zip` or `teamscrawl_<version>_windows_arm64.zip`, unzip it, and run `teamscrawl.exe`. Add the unzip directory to `PATH` if you want to launch it without the full path. The Outlook source is macOS only.

## Acceptance and verification

- `make acceptance-calendar` runs the calendar acceptance tests against a real Teams cache and a real Outlook store. For this release all 19 checks passed on real copies, recording only counts, timings, paths and field names: every calendar record maps, field parity, rich-data counts, recaps, time zones, sync-state census, append-only, and for Outlook the sources row, the container, the twin rate (145 of 145 Teams–Outlook twins matched), the version rule, safety, append-only, reporting-only and cost (the first Outlook read adds no measurable peak memory over a Teams-only sync; copy and scan take about 3 seconds).
- A fresh agent given only `teamscrawl skill` and the binary answered the calendar questions correctly on the fixtures, including linking an Outlook profile and confirming that the merged events kept their Teams meeting data.
- macOS release verification checks the downloaded darwin binaries and the Homebrew install; Windows release verification checks the zip files against `checksums.txt`, the PE architecture, that the binaries are intentionally unsigned, and runs `teamscrawl.exe --json version`.

## Signing note

The macOS release binaries are Developer ID signed and notarized when the release workflow has the Apple signing secrets. The Windows amd64 and arm64 zip assets are intentionally unsigned.
