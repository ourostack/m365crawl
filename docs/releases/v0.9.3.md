# m365crawl v0.9.3

**Everything your agent needs to start is in the CLI.** We gave 0.9.2 to a fresh agent with nothing but `--help` and command output. It finished every job, and it showed us where the CLI made it guess. This release fixes those places, and stops reporting empty Office responses as failures.

## What the archive holds, at a glance

The bare `m365crawl` overview now lists every kind of data in the archive: chats, mail and the calendar, plus documents, notes, people and transcripts, each with counts, registered and failed sources, and the last capture. "Start here" names `docs list`, `notes search` and `people`.

```sh
m365crawl
m365crawl docs --help
m365crawl --max-age 0 docs list --application PowerPoint --surface recent --limit 5
m365crawl --max-age 0 docs sources
m365crawl --max-age 0 people --limit 10
```

## Truthful document sources

- An Office recent or recommended file that is a successful service response listing no documents is now a complete capture with zero rows and reason `office_response_listed_no_documents`, not a failure. Only the exact empty shapes seen in real files qualify; error, throttled and unknown responses still fail.
- A failed source is identifiable and actionable: every row carries `kind` and `locator_tail`, and failed rows carry `fix` and `effect`, which says whether the last good capture stays current.
- `docs list` and `docs search` take `--application` and `--surface`. `docs --help` defines the surfaces, the clocks and what `unresolved` means.

## Fewer guesses elsewhere

- `--format log` works on every command (`docs_list={...}`).
- Text output names the time zone on every archived time of day, so a text day is not mistaken for the UTC day in JSON.
- Unscoped `people` says what it included and the ownership caveat for native Outlook observations. `people --help` explains what `last_seen_at` means, which ID kinds appear, and where `--account` values come from.

## Breaking JSON changes

- `source_id` in `docs sources`, `notes sources` and `people sources` rows is `null`, not `0`, for a source that has never had a capture admitted. Use `kind` and `locator_tail` to identify such a row.
- The overview no longer has a top-level `note` or `next` step about native people sources; the new people row carries that information.

## Install and upgrade

On macOS, use `brew install ourostack/tap/m365crawl` or `brew upgrade m365crawl`. Alternatively, download the matching Darwin tarball and verify it against `checksums.txt`. Darwin binaries are Developer ID signed and notarized.

On Windows, download the matching amd64 or arm64 zip, verify its checksum, unzip it and replace `m365crawl.exe` in your user-owned installation. **Windows binaries are intentionally unsigned.**

The archive schema is unchanged (11). Run `m365crawl doctor` after upgrading.
