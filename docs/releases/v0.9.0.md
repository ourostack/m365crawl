# m365crawl v0.9.0

**Find the name. Inspect the claims.** Native Outlook people observations now join the existing people list, with stable follow-ups that show what the source actually said. Your agent can inspect names, email and directory claims, differing copies and coverage without turning a cached address into a guessed current contact.

## From a name to its source evidence

Register the available Mac Outlook people cache once, then search and inspect:

```sh
m365crawl people sync
m365crawl people --query "name or address" --limit 10
m365crawl people show person-observation:ID
m365crawl people sources
```

Replace `person-observation:ID` with an ID returned by the people list. For supported copied HxStore inputs, use `people sync --root DIR`, with files laid out as `<root>/<profile>/HxStore.hxd`. This copied-input branch is qualified on macOS and Windows; default native discovery is Mac Outlook only. Windows OWA people discovery is not included.

Ordinary reads refresh registered sources only. `--max-age 0` inspects the archive without another capture. Existing Teams and mail people keep their identifiers and item fields; native rows are separate, unresolved observations. Use the native observation ID with `people show`, not a Teams person ID or `mail:` address.

## Keep the uncertainty, not just the latest copy

Immutable representations retain native fields and first capture/source clocks. Later captures track membership and reuse without rewriting those original clocks. Partial or failed captures preserve prior observations and contradictions; source coverage stays visible beside served last-good data. Native versions are evidence, not a clock that chooses the current person.

A profile-owner link does not prove a subject's tenant. Matching email addresses do not automatically merge directory identities. Account filters leave unresolved native subjects out with a notice, and native sync/show/source commands reject unsupported subject-account filters. Cache refresh time is not last contact; the existing legacy `last_seen_at` may also reflect membership.

This release also fixes optional-reader panic cleanup and peer reporting, same-command source coverage, incomplete identity collision checks, and limited-list ordering. Unsafe source leaves and unsupported default providers fail with explicit guidance. The archive upgrades additively to schema 10 through normal commands; do not manually alter or vacuum it. See [the changelog](https://github.com/ourostack/m365crawl/blob/v0.9.0/CHANGELOG.md) and [command reference](https://github.com/ourostack/m365crawl/blob/v0.9.0/docs/commands.md).

## What remains planned

Teams chats/calendar, Windows Outlook cached mail, indexed OneNote notes and explicit transcript fetching remain available. Windows OWA calendar is planned, not part of this release. Automatic subject-identity resolution, current full-attendee joins, document metadata/text, cached Loop and additional cloud consumers still need their connected workflows to ship. Planner/To Do assigned tasks and private Copilot history remain outside this expansion.

## Install

On macOS, run `brew install ourostack/tap/m365crawl`; for an existing cask installation, run `brew upgrade m365crawl`. Alternatively, download `m365crawl_0.9.0_darwin_arm64.tar.gz` or `m365crawl_0.9.0_darwin_amd64.tar.gz` and verify it against `checksums.txt`. Darwin binaries are Developer ID signed and notarized by Apple. The terminal or agent host needs Full Disk Access for protected desktop caches.

On Windows, download `m365crawl_0.9.0_windows_amd64.zip` or `m365crawl_0.9.0_windows_arm64.zip`, verify it against `checksums.txt`, unzip it under your user profile and run `m365crawl.exe`. **Windows assets are intentionally unsigned.** Replace the existing executable to upgrade and use normal commands for the additive archive migration. The archive directory and existing database/sidecars must satisfy the owner-private Windows rules.

After installing, run `m365crawl doctor` and give your agent the version-matched guide from `m365crawl skill`. Support grows from real data and verified workflows. For another app or missing workflow, work with your agent to [open a prompt request](https://github.com/ourostack/m365crawl/issues/new?template=prompt-request.yml); do not attach private content, caches, archives or credentials.
