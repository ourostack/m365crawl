teamscrawl mirrors the Microsoft Teams desktop app's local cache into a SQLite archive on your Mac, with full-text search, unread state, mentions and the activity feed. An AI agent can read your Teams history in milliseconds, offline and read-only: it never talks to the Teams service, never reads your Teams credentials and never writes to Teams' storage.

## Install

```sh
brew install ourostack/tap/teamscrawl
```

Or download `teamscrawl_<version>_darwin_arm64.tar.gz` or `teamscrawl_<version>_darwin_amd64.tar.gz` from this release and check it against `checksums.txt`. The last line of these notes says whether this release's binaries are Developer ID signed and notarized or unsigned. The Homebrew cask clears the macOS quarantine flag either way; for an unsigned binary downloaded by hand, run `xattr -dr com.apple.quarantine teamscrawl` once.

Then run `teamscrawl doctor`. It tells you whether your terminal or agent host needs Full Disk Access (see [docs/full-disk-access.md](https://github.com/ourostack/teamscrawl/blob/v0.1.0/docs/full-disk-access.md)).

## Highlights since alpha.1

- **`watch`.** Streams JSON Lines as Teams writes its cache: one `message` or `activity` line per new, edited or deleted item and one `sync` line per sync. It uses file events with a poll as the safety net, and exits 0 on Ctrl-C. Measured against a real cache, a message's sent time to its output line took about 12 to 32 seconds (median about 17 seconds), most of it Teams' own flush delay.
- **Lower memory.** Peak memory during a full sync fell from about 0.8 GB to about 0.2 GB on a real cache, with identical archive rows. The reader keeps values only for the three databases teamscrawl decodes and re-reads large values from the snapshot on demand.
- **Verified against independent readers.** On a real cache, the native V8 decoder matched Node's `v8.deserialize` on every one of about 18,000 allowlisted records (0 mismatches), and teamscrawl's conversation and message volumes matched an independent Python reader (`ccl_chromium_reader`) at 100%. These runs are local only and record counts, never content.
- **100% statement coverage** of every function in `internal/...`, enforced in CI, plus an end-to-end suite that runs the built binary against a committed fixture written by a real Edge browser.
- **Text that reads as text.** A bot's Adaptive Card, hero or connector card gives its title, text blocks and facts as `text`; call and meeting events read `Call ended · 23m`; thread events read `Member added`; call recording and transcript notices read `Call transcript available`. Call events show a sender. Untitled group chats are named after their members (`Ana, Ben, Chao +2`). The original record stays in `raw_json`.
- **Navigation for agents.** `--team <name|id>` limits `conversations`, `messages`, `search`, `unread` and `activity` to one team. Channel thread roots carry `reply_count` and `last_reply_at`. Truncated lists add `total`, the exact number of matches. `search` works with filters alone (`--mentions-me`, `--from`, ...). `conversations --query` ranks exact names first. `activity --type` takes a comma-separated list.
- **Friction fixes from a fresh-agent run.** A read that syncs first prints one stderr line (`teamscrawl: syncing — archive is 2h14m old (max-age 15m)`) and its result gains `synced: {seconds, status}`. Messages that mention you carry `mention_kind` (`person`, `channel`, `team`, `tag`, `everyone`), and `--direct-mentions` on `messages`, `search` and `activity` keeps only mentions by name. Activity items carry `actor_id` and `actor_name` (who reacted, replied or mentioned). `teams` lists teams with channel count, last activity and unread count, and `--team` takes what it prints. `unread --since 7d` counts only recent unread messages. All additive: no field was renamed or removed.
- **Partial syncs and an agent guide in the binary.** Each Teams source commits on its own: a sync where one source fails and another succeeds reports `partial` with per-source results, prints the report on stdout and a `partial_sync` error (exit 1) on stderr. `archive_age_seconds` counts from the last fully successful sync, per account. `teamscrawl skill` prints the agent guide embedded in the binary, so it always matches the installed version. `teamscrawl --version` and `teamscrawl version` print the version, commit and build date as JSON. `doctor` also checks `archive_newer`, `archive_upgrade` and `last_sync_status`. A second Ctrl-C exits 130 at once.
- **New error codes.** `partial_sync`, `interrupted` (a command stopped by Ctrl-C or a signal) and `archive_newer` (an archive written by a newer teamscrawl is refused for writing, reads still work).
- **Complete documentation.** [SPEC.md](https://github.com/ourostack/teamscrawl/blob/v0.1.0/SPEC.md) is the normative specification, with every error code and exit code; [docs/commands.md](https://github.com/ourostack/teamscrawl/blob/v0.1.0/docs/commands.md), [docs/how-it-works.md](https://github.com/ourostack/teamscrawl/blob/v0.1.0/docs/how-it-works.md) and [docs/full-disk-access.md](https://github.com/ourostack/teamscrawl/blob/v0.1.0/docs/full-disk-access.md) cover the rest.
- **Signing pipeline.** Release builds are Developer ID signed and notarized automatically when the Apple signing secrets are available to the release workflow. The release workflow now runs `make check` before it publishes.

## Upgrading from alpha.1

Install the new version over the old one; your archive is upgraded in place.

- The first `sync` (also the first `watch`, or a read command's implicit sync) re-derives message text, sender names and untitled-chat names from each stored row's raw record, then rebuilds the text indexes. This covers every row in the archive, including messages Teams has since evicted from its cache, so old bot cards, call events and thread events read as text after that one sync. You do not need Teams to still hold them.
- The upgrade is not a Teams change: the report shows `migrated: {from, to, rows}`, the rows count as no update, and `watch` prints one `migrated` line and no `edited` lines. The report can say `status: unchanged` and `migrated` together, because the cache itself did not change.
- Read-only commands (`search`, `messages`, ...) never migrate. Until the first sync they show the alpha's text and `needs_sync: true`. An implicit sync (`--max-age`) migrates like any other sync.
- Do not point alpha.1 at an upgraded archive. This build refuses to write an archive from a newer build (`archive_newer`), but alpha.1 does not know to refuse and would mix its older text into rows the new version keeps.
- A few people's display names can differ from what a fresh sync would give, because a name follows the most recent sighting.

No JSON field was renamed or removed, and exit codes did not change. See [CHANGELOG.md](https://github.com/ourostack/teamscrawl/blob/v0.1.0/CHANGELOG.md).

## Known limits

- teamscrawl sees only what the desktop app has cached. History you never scrolled to may be missing, and Teams evicts old messages from its cache. The archive never deletes a message, but it holds only what a sync has seen, so sync regularly.
- macOS and the new Teams app only. Full Disk Access is required for the app that runs it.
- Read-only: no sending, reacting or marking read. Attachments and media are not downloaded; files and links are stored as metadata.
- Some `msGraph` activity rows (Microsoft 365 notices) have an empty conversation, sender and text, and so no `actor_*`. A read of a never-synced archive with `--max-age 0` exits 0 with `needs_sync: true`; check the flag before treating an empty result as "no match". Untitled group chats named after a few members can share a name; select them by `conversation_id`.
- `reply_count` is counted from archived replies and can be lower than Teams shows if the cache never held the replies.
- `watch` latency is mostly Teams' own cache flush, so expect tens of seconds, not instants.
- The archive holds message content verbatim, including anything people pasted (links with tokens, credentials). Treat the database like the chats it contains. It is mode 0600 in a 0700 directory.
- The real-cache acceptance runs are local only; CI proves the same decoders against the committed fixture and V8 test vectors.
- If Teams changes its storage layout, `sync` fails with a named error or reports counted omissions instead of guessing.
