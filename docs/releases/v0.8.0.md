# m365crawl v0.8.0

**Your notes can now join the conversation.** Find OneNote indexed text and OCR alongside Teams chats, Outlook mail and fetched meeting transcripts, then follow a stable note ID to the text, hierarchy, flags and source coverage. This release turns the indexed-notes backend into a connected archive workflow, not a promise of a complete notebook export.

## Find the note, then read the evidence

Register available Mac OneNote indexes once:

```sh
m365crawl notes sync
m365crawl search "budget review"
m365crawl notes search "budget review"
m365crawl notes show note:ID
m365crawl notes sources
```

Replace `note:ID` with an ID returned by search or list. For a supported directory of copied indexes on macOS, Windows or Linux, use `m365crawl notes sync --root DIR`. Ordinary reads refresh only registered sources; `--max-age 0` reads the archive without capturing again. Notes-only commands do not require Teams, Outlook, a browser or a live service request.

Search returns focused results with stable IDs. Detail preserves indexed text/OCR, native elements, flags and hierarchy; source coverage stays visible even when a query has no hits or selected fields omit content. Partial or failed captures retain prior page representations, and missing pages are not treated as deletions. See the [synthetic worked example](../../README.md#scope-and-requesting-support) and [command reference](../commands.md#indexed-notes).

## What this does not claim

An index is not an original document: page visual layout, web URLs, authors and account ownership are not invented. Default discovery is Mac OneNote. Native Windows OneNote app-cache discovery, additional app layouts and live WAL capture remain deferred. Supported rollback-mode copies are portable; active journals, WAL/SHM and unsafe or inconsistent files are refused. Capture uses private copies and SQLite-compatible locking, without writing to the application indexes.

Windows Outlook cached mail and Teams calendar remain supported. Windows OWA calendar is not included; it is a planned continuation, not part of this notes release. People enrichment, document links/text, cached Loop and other cloud consumers remain planned until their connected workflows ship. Planner/To Do assigned tasks and private Copilot history remain outside the current expansion.

The archive upgrades additively to schema 9 through normal commands. Existing mail identifiers and legacy workflows are preserved. Do not manually alter or vacuum the archive. The release also corrects note field selection, retained-source refresh, cancellation diagnostics, coherent detail reads and projected text output, and propagates sign-in archive-table errors instead of treating them as absent tables. See [CHANGELOG.md](../../CHANGELOG.md) for the assembled changes.

## Install

### macOS

```sh
brew install ourostack/tap/m365crawl
```

For an existing cask installation, run `brew upgrade m365crawl`. Alternatively, download `m365crawl_0.8.0_darwin_arm64.tar.gz` or `m365crawl_0.8.0_darwin_amd64.tar.gz` and verify it against `checksums.txt`. Darwin binaries are Developer ID signed and notarized by Apple. The terminal or agent host needs Full Disk Access to read protected desktop-app caches.

### Windows

Download `m365crawl_0.8.0_windows_amd64.zip` or `m365crawl_0.8.0_windows_arm64.zip`, verify it against `checksums.txt`, unzip it under your user profile and run `m365crawl.exe`. Windows assets are intentionally unsigned. Replace the existing executable to upgrade; use normal commands to upgrade the archive. Its containing directory and existing database/sidecars must satisfy the owner-private Windows rules.

After installing, run `m365crawl doctor` and give your agent the version-matched guide from `m365crawl skill`. Support grows from workflows and real data we can qualify. For another app or missing workflow, work with your agent to [open a prompt request](https://github.com/ourostack/m365crawl/issues/new?template=prompt-request.yml); do not attach private content, caches, archives or credentials.
