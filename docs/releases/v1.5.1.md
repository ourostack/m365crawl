# m365crawl v1.5.1

**Mac mail finds its footing again after an Outlook cache-layout change.**

A compatible patch on the stable 1.x line. Existing commands, flags, output fields and archive schema are unchanged.

## Fixed

- Outlook for Mac mail sync reads the measured message-detail layout `0xc9/0x610` alongside the existing `0x60f` layout. It uses the correct string base, rather than merely admitting the new tag, and continues refusing unknown or short layouts.
- The mail mapper version advances so the next ordinary sync rereads an unchanged Outlook store and can recover from the earlier unsupported-layout failure.

## Added

- An [agent field guide](../agent-field-guide.md) with a quick start, a worked coverage example, common read/write pitfalls and a privacy-aware handoff checklist.

## Upgrade and coverage

Run an ordinary `m365crawl sync` after upgrading, then inspect its source results and `m365crawl doctor`. The layout fix does not prove complete mailbox or server history. Other unsupported layouts, including attachment `0x16a/0x31e`, remain explicitly reported omissions; this release does not claim their acquisition.

WorkIQ service qualification on Windows, several populated Windows Outlook content mailboxes and a live protected-document view-only refusal remain unverified. No new source or access permission is granted by this patch.

## Install

On macOS, use `brew install --cask ourostack/tap/m365crawl` or `brew upgrade --cask m365crawl`, or verify the matching Darwin tarball against `checksums.txt`. Darwin binaries are Developer ID signed and notarized by the normal release pipeline.

On Windows, download `m365crawl_1.5.1_windows_amd64.zip` or `m365crawl_1.5.1_windows_arm64.zip`, verify it against `checksums.txt`, unzip into a user-owned directory and run `m365crawl.exe`.
**Windows binaries are intentionally unsigned.**
