# m365crawl v0.9.6

**Two fresh agents told us where the CLI made them guess, and this release answers them. It also reads the list of documents Office says you opened recently.**

## The questions two cold agents asked

We gave installed 0.9.4 and 0.9.5 to agents with nothing but `--help` and command output. Both finished every job. These are the places they had to guess, now answered in the CLI itself.

- **"How many of these were posted by an app?"** `application_evidence_coverage` has `posted_by_app`, and says when it is a lower bound. `--fields app_summary` gives the app, the reply-to message and the citation total without the whole nested object.
- **"What does this loss code mean?"** Every loss and failure code has a one-line meaning, in the help and on the message that carries it.
- **"Did search even look at Loop?"** `search` reports, per source, what it `returned` and what it `matched` before the limit, exactly or as `matched_at_least`. Text output says `6 Loop hits not shown; use --source loop and raise --limit` when a source was crowded out.
- **"Is this the current Loop page?"** No, and the rows now say so: `latest cached snapshot`, `partial_snapshot`, and whether the archived record is gone from the app's cache.
- **"What tables does `sql` have?"** `sql --help` lists every table with what it holds and shows how to list a table's columns.

```sh
m365crawl messages --since 1d --fields id,sender_name,app_summary
m365crawl search "launch plan" --limit 5
m365crawl sql --help
```

## Office registry documents

Office keeps a registry of recently opened documents in a local SQLite file. `docs sync` now reads it as document metadata. Nothing the registry refers to is opened, checked or resolved.

```sh
m365crawl docs sync
m365crawl docs list --application registry
m365crawl docs sync --registry-file /path/to/copy.reg
```

- Each entry is a document observation with `variant` `office_registry`, the registry's own claims in `registry_native` and its opened time in `opened_at`.
- The registry states no modification time, so `modified_at` is null and `--since`/`--until` never match these rows.
- On Mac, a default `docs sync` finds the registry files. On Mac or Windows, `--registry-file FILE` reads one ordinary local copy.
- The source file is opened read-only and copied privately while a SQLite shared lock is held. It is re-checked before and after the copy, and only the private copy is parsed.

## Breaking changes

- Document `source_coverage.scope` is renamed from `office_json_metadata` to `office_document_metadata`, because it now covers Office JSON and Office registry sources.
- A default `docs sync` whose Office JSON caches are missing or refused now exits 0 when a registered source was attempted or the registry was usable, and reports the refusal under `discovery`. When nothing is usable it still exits 3 with the refusal's code.

## Upgrading

The archive moves to schema 14. The change only adds columns; existing rows are not rewritten. Run `m365crawl doctor` after upgrading, then `m365crawl docs sync`.

See the [changelog](https://github.com/ourostack/m365crawl/blob/v0.9.6/CHANGELOG.md) and [SPEC](https://github.com/ourostack/m365crawl/blob/v0.9.6/SPEC.md) for the exact contract.

## Install and upgrade

On macOS, use `brew install ourostack/tap/m365crawl` or `brew upgrade m365crawl`. Alternatively, download the matching Darwin tarball and verify it against `checksums.txt`. Darwin binaries are Developer ID signed and notarized.

On Windows, download the matching amd64 or arm64 zip, verify its checksum, unzip it and replace `m365crawl.exe` in your user-owned installation. **Windows binaries are intentionally unsigned.**
