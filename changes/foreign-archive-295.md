### Changed

- A read syncs first only into the default archive or an archive this machine's sources feed (#295). Reading a scratch file, a copy (even of your own archive), an archive from another machine or a test archive with `--db` no longer mixes this machine's live Teams and Outlook data into it, or migrates it: the read answers from the archive as it is, with `implicit_sync: "foreign_archive"` and a notice that names the explicit `m365crawl --db PATH … sync` to run if you do want this machine's data in it. A read on a `--db` path with no archive no longer creates one (`implicit_sync: "no_archive"`). Each sync now records, per source, a hash of a random machine ID, the source root and the archive's path, so an archive you already sync into keeps syncing at its path (after moving one, run `sync` on it once); an archive from an earlier version is adopted on its first read when its sync history names a Teams profile this machine has. Explicit `sync`, `watch`, fetch and capture commands are unchanged.
