# teamscrawl agent instructions

## Development rules

- Run every Go command with `GOWORK=off`. The Makefile and CI already do this.
- Run `make check` before opening a PR. It runs tidy, format, vet, lint (golangci-lint, govulncheck, actionlint), unit tests with the race detector, and the e2e tests.
- Every change reaches `main` through a PR with green CI. Pin every GitHub Action by full commit SHA with a trailing `# vX.Y.Z` comment.
- Never commit real Teams data, in fixtures, tests, logs, PR text or commit messages. Fixtures are synthetic and generated by the fixture generator (regenerate `testdata/teams-fixture` with `make fixture`, which drives Microsoft Edge through Playwright in `scripts/fixture`; after regenerating, refresh the goldens with `go test ./internal/indexeddb -run TestFixtureGolden -update`, review the diff and commit the tree, `PROVENANCE.json` and `expected/` together; the generator fails loudly unless the origin directory name and the snappy, blob and v21 envelopes are all present; `testdata/` files are binary and never reformatted).
- Never write to Teams' storage. Never decode credential material: the deny-only rule and the denylist are described under "Credential denylist" below. Never read Teams tokens.
- Every function in `internal/...` is 100% statement-covered by `go test ./...` (unit tests; the e2e and acceptance tags do not count). `make coverage` (`scripts/check-coverage.sh`) enforces it in the CI `coverage` job and fails on any uncovered function that is not carved out. Write tests that assert behavior, with synthetic data only. Prefer injecting a failure (an interface or a function variable) over listing a function.
- Carve-outs live only in `coverage/allow/<package>.txt` (one file per Go package, for example `internal-leveldb.txt`), one entry per line: `<path relative to the repo root>:<FuncName> <reason>`, the name exactly as `go tool cover -func` prints it. List a function only when its uncovered statements are unreachable from a deterministic test without unreasonable contortion (OS or platform glue, a syscall error that cannot be forced portably); "it would take effort" is not a reason. A stale entry (the function is already 100% or gone) fails the gate, so the list only shrinks. See `coverage/allow/README.md`. `COVERAGE_PACKAGES` narrows the check for local runs.
- Signal handling lives only in `cli.Main`. Lower layers take a `context.Context` and clean up when it is cancelled. The first SIGINT or SIGTERM cancels the context; a second one exits immediately with status 130 (`exitForced`), which can leave a snapshot directory in TMPDIR; a later sync sweeps snapshots older than an hour.
- Tests that rely on `chmod 000` must skip when `os.Geteuid() == 0`.
- Do not add AI attribution anywhere: no `Co-Authored-By` trailers, no "Generated with" lines, no AI credit in commits, PRs, code comments or docs.
- Use conventional commit messages (`feat:`, `fix:`, `ci:`, `chore:`).

## Credential denylist

- The rule is deny-only (operator ruling, 2026-10-02): agents get open access to all Teams data except credentials. `internal/teamsdesktop/deny.go` holds the denylist (`Denied`): a database or object store name that starts with `Teams:auth` or contains `auth`, `token`, `credential`, `secret`, `cookie`, `msal`, `oneauth`, `key-store`, `keystore`, `keyval`, `session`, `key-value`, `keyring`, `crypto`, `encrypt`, `pkce`, `bearer`, `password`, `refresh` or `adal`, or has `aad`, `keys`, `jwt` or `e2ee` as a whole `-`/`_`/`:`/`.`-delimited segment, ignoring case, is never opened for values, decoded, listed or logged. Only the counts `denied_database` and `denied_store` appear. It over-denies on purpose.
- `internal/teamsdesktop/read.go` holds the three typed managers (`replychain-manager`, `conversation-manager`, `activity-manager`), which have mappers. `internal/teamsdesktop/generic.go` (`ReadGeneric`) reads every object store that is not denied and not consumed by a typed mapper (typed databases' other stores included) into the `records` table, in memory-bounded batches (a census first, then one open per batch that keeps only that batch's stores by id, each origin dropped and the heap collected before the next). Values are scrubbed (`scrub.go`: JWTs, `access_token`-style keys, `sig=` parameters become `[redacted]`, counted as `redacted` in the sync report), and each sync clears (`PurgeDenied`) archived rows whose database or store name the denylist now matches: the one place the archive deletes content.
- Changing the denylist is a design change: edit `deny.go`, its tests, SPEC.md section 2 and the fixture's credential decoys in the same PR. Weakening it (removing a term) needs a review of the real cache's database names first, on a machine that holds one. `TestRealNoAuthDecoded` asserts on a real cache that no denied database yields records.
- Adding a typed mapper for a generic database is a normal change: add the mapper, a fixture record, tests and a SPEC.md row; the database then leaves `records` for its own table.

## Archive rules

- Never delete archived rows because they left Teams' cache. `deleted_at` (and `records.removed_at`) is a sticky tombstone (SPEC.md section 3.2). No `DELETE` against `messages`, `conversations`, `people`, `activity` or `records`.
- Never run `VACUUM` on the archive, in code or by hand. `message_fts` and `conversation_fts` reuse the rowid of the `messages` and `conversations` rows they index (both are rowid tables with no explicit integer primary key), and SQLite may renumber such rowids on `VACUUM`, which would detach every index entry from its row. The constraint is the rowid link, not FTS itself; if you add an explicit `INTEGER PRIMARY KEY` to those tables the constraint changes, so update `store/schema.go`, `rederive.go` and SPEC.md section 3.3 together.
- A change to a mapper that alters a derived field (text, sender name, conversation display name) must raise `store.DerivationVersion` and teach `Rederive` to recompute the field from `raw_json`. A change that alters what a decode produces must raise `teamsdesktop.DecoderVersion` so the next sync re-reads an unchanged cache.
- Schema and field changes go through `CHANGELOG.md`: adding a field is compatible, renaming or removing one is a breaking change.

## Documentation

- `SPEC.md` is normative. Change behavior and SPEC.md in the same PR, and add every new error code to its error table.
- `docs/commands.md` reproduces `teamscrawl --help` and each `teamscrawl <command> --help`. When a flag or help text changes, update it and check it against the binary.
- `.agents/skills/teamscrawl/SKILL.md` is what a fresh agent reads first. Keep it short and consistent with SPEC.md; example JSON in docs comes from the committed fixture, never from a real cache.
- Never put real Teams data in docs, examples, issues or PRs.

## Real-cache acceptance tests

- `TEAMSCRAWL_REAL_CACHE=1 make acceptance` runs `acceptance/` (build tag `acceptance`) against the live Teams cache on this Mac. It needs Full Disk Access, Node 22, and python3 with two read-only reference clones: `~/code/_refs/ccl_chromium_reader` and `~/code/_refs/ccl_simplesnappy` (override with `CCL_READER`, `CCL_SNAPPY`; `TEAMSCRAWL_PYTHON` picks the interpreter). `ccl_count.py` stands in empty `brotli` and `zstd` modules, so no `pip install` is needed. CI never runs it, and without `TEAMSCRAWL_REAL_CACHE=1` the real-cache tests skip.
- `TestRealDifferential` decodes every typed record twice, with `v8.Deserialize` and with Node's `v8.deserialize` (`acceptance/diff.mjs`), and compares canonical JSON. `TestRealVolumes` and `TestRealConversationAccounting` compare record and message counts with `ccl_count.py` on the same snapshot; the reference counts only the newest version of each record, so superseded versions and deletions are excluded by design.
- `TestRealRecency` checks that the newest archived message is within an hour of the newest conversation activity, and `TestRealBlobsResolve` asserts that a real sync reports zero `blob_missing` omissions. `TestRealNoAuthDecoded` also scans the archive for anything shaped like a bearer token.
- The tests log counts, timings and field paths only. Never add a log line, failure message or comment that prints a name, id or content from the real cache.

## Test hooks

- `TEAMSCRAWL_TEST_PAUSE_AFTER_SNAPSHOT=<duration>`: when set, the syncer prints `teamscrawl-test: paused after snapshot` to stderr and then sleeps that long after the snapshot is taken. Used by the e2e tests, which signal the process once the marker appears, and by a few unit tests that cancel a sync during the pause. Never set it outside tests.
- `TEAMSCRAWL_TEST_PAUSE_IGNORES_CANCEL=1`: makes that pause ignore cancellation, so a graceful stop cannot finish and the e2e test can prove that a second SIGINT or SIGTERM force-quits with exit 130.
